# 账号、注销与站点策略

这份文档面向**部署方**，说明账号侧的几条链路怎么工作、在哪里改。

---

## 1. 邮箱与账号强绑定

邮箱是账号的根凭证：可以用它登录、用它找回密码、给它发登录验证码。
所以它不能像用户名那样在「编辑资料」里随手改。

### 1.1 客户端

- 「设置 → 账号 → 编辑资料」只改用户名；
- 「设置 → 账号 → 邮箱」进入独立的「更换邮箱」页，需要：
  1. **当前密码**（证明是本人，而不是捡到手机的人）；
  2. **新邮箱收到的验证码**（证明这个邮箱确实归你）。

换绑成功后：

- 旧邮箱**立刻**不能再登录、也不能再收验证码；
- 其它设备上的登录被撤销（当前设备保留）。

### 1.2 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/change-email/code` | 校验密码后给**新**邮箱发验证码 |
| POST | `/api/auth/change-email` | 密码 + 验证码，完成换绑 |
| PATCH | `/api/auth/me` | 只接受 `username`；带 `email` 会回 `email_locked` |

> 验证码用途是 `change_email`，和注册/登录分开计数（限流按用途 + 邮箱维度）。

## 2. 注销账号

注销是**两段式**的：申请 → 冷静期 → 物理删除。

```
客户端点「注销」
        │  密码确认
        ▼
POST /api/auth/delete
        │  写入 deletion_requested_at / deletion_scheduled_at
        ▼
冷静期（面板设置的天数，默认 7 天）
  · 账号仍可登录 → 账号页顶部显示「将于 X 删除」+ 撤销按钮
  · 其它设备被踢下线
        │
        │  到期（启动扫描 / 定时扫描 / npm run prune）
        ▼
物理删除：users 行 + 全部登录会话 + userdata/<id>/ 目录
```

### 2.1 关键规则

- **删除范围**：账号行、所有登录会话、`userdata/<id>/`（含头像）。
  邮件验证码按邮箱存，不单独删（本来就只保留一天）。
- **到期即失效**：即使清理任务还没跑到，`resolveSession()` 也会拒绝
  已到期账号的 token —— 用户看到的是「登录已失效」，不会出现
  「到期了却还能用」。
- **保持时间**：已经排期的注销不会因为改配置而提前或推迟。
  改冷静期只影响**新**申请 —— 否则「还剩几天」会变得不可信。
- **本地数据**：冷静期内客户端**保持登录**，账号页顶部显示「已申请注销」
  + 撤销按钮；只有冷静期为 0（申请即删除）时才清掉登录态。
  已安装的小程序与本机存储不在删除范围（可在「应用管理 / 存储」里单独清理）。

### 2.2 配置

管理面板 →「站点」→ 注销账号：

| 项 | 环境变量 | 说明 |
| --- | --- | --- |
| 冷静期（天） | `ACCOUNT_DELETE_DELAY_DAYS` | `0` = 申请即删除，请谨慎 |
| 到期扫描间隔（分钟） | `ACCOUNT_PURGE_INTERVAL_MINUTES` | `0` = 只在启动与 `npm run prune` 时清理 |

也可以直接改 `.env`，但**手工改 `.env` 仍需重启**；面板保存会立即应用到内存。

### 2.3 面板立即删除

管理面板 →「用户」→「删除账号」：

- **跳过冷静期**，立刻删除（同样删账号行、会话、`userdata`）；
- 用于「用户写信要求马上删」「这个号在发垃圾内容」；
- 不可恢复，所以按钮上有二次确认。

「撤销注销」用于用户反悔或误操作，效果与客户端撤销一致。

## 3. 登录设备

「设置 → 账号 → 登录设备」是二级页，分三段：

| 分区 | 数据来源 | 能做什么 |
| --- | --- | --- |
| 当前设备 | `/api/auth/sessions` | 只读 |
| 其它在线设备 | 同上 | 逐条「退出这台设备」 |
| 历史登录 | `/api/auth/sessions/history` | 只读（已退出 / 已过期 / 离线） |

- 历史保留最近 **100 条**，按最近活跃时间倒序；
- 句柄只返回 token 哈希的**前 16 位**，不足以还原 token；
- 撤销立即生效：每次鉴权都会查 `login_sessions`，不是等过期。

## 4. 市场分段加载与本地缓存

### 4.1 每页条数由服务端决定

管理面板 →「站点」→ 市场分页：

| 项 | 环境变量 | 说明 |
| --- | --- | --- |
| 每页条数 | `MARKET_PAGE_SIZE` | 客户端不传 `limit` 时使用 |
| 每页上限 | `MARKET_MAX_PAGE` | 挡住 `?limit=999999` |

客户端**不写死条数**：响应里的 `meta.limit` 会被保存下来，
后续翻页按同一个数请求，避免「第一页 20 条、第二页 50 条」的跳变。

主页用游标分页（`nextCursor`），搜索用 offset 分页 —— 两者都只加载
「用户滑到的那几页」。

### 4.2 本地缓存

- 命中缓存的顺序：**先显示上次的列表 → 再静默刷新**；
- 缓存按「服务器 + 分类 / 关键词 + 标签」隔离，切换服务器后旧缓存自动失效；
- 上限：每个分类 200 条，搜索最多 10 组关键词 × 40 条；
- 清空时机：退出登录、被踢下线、注销账号、App 退出（detached）。

> 缓存里只有公开的市场数据（应用列表），不含账号隐私。
> 清不掉也不影响正确性，因为读的时候会校验 `serverUrl`。

## 5. 封禁：时长 + 原因

封禁是「**账号还在，但登不上**」。和注销的区别：数据一点不删，解封后照常用。

### 5.1 填法

管理面板 →「用户」→「管理」→ 封禁：

| 字段 | 说明 |
| --- | --- |
| 封禁时长（天） | 正整数 = 天数；**`-1` = 永久**；`0` 与其它负数会被拒 |
| 原因（可选） | 最多 255 字，会显示在用户的登录失败提示里 |

上限 3650 天（10 年）—— 再长就等于永久，还容易多打一个 0。

### 5.2 三条落地规则

1. **立刻生效**：封禁会撤销该用户全部登录会话。只改状态位的话，
   已经登录的设备还能揣着旧 token 用到过期。
2. **到期自动放行**：`resolveSession()` 与登录接口都会比较 `banned_until`，
   到点立刻放行 —— 不依赖扫描任务是否跑到。扫描任务只是把 `status`
   改回 `active`，让面板别再显示「已封禁」。
3. **永久封禁不能被子句放过**：永久封禁的 `banned_until` 是 `NULL`，
   到期扫描的 SQL 显式排除 `NULL`（SQL 里 `NULL <= now` 恒为假，
   但 JS 里把 `null` 当 0 比较就会「一秒后自动解封」）。

用户看到的提示形如：

```
这个账号已被封禁至 2026-11-22 16:00（UTC）（原因：发广告）
这个账号已被永久封禁（原因：批量注册）
```

> 客户端把 `account_banned` 与 `account_disabled` 都按「已下线」处理：
> 清掉本地 token 并弹窗，提示语用服务端给的那一句。

### 5.3 数据落在哪

`users` 表三列：`status` / `banned_until` / `ban_reason`。
解封时**三个一起清** —— 只清 `status` 会留下「已解封但还显示封禁原因」的鬼状态。

老库由启动时的 `ensureUserColumns()` 幂等补列（列已存在时吃 1060）。

## 6. 面板代改用户资料

「用户 → 管理」打开的详情页里能改用户名、注册邮箱、头像，还能看到
注册时间/IP、在线会话数、`userdata` 占用。

| 项 | 说明 |
| --- | --- |
| 用户名 | 与注册同一套规则（`lib/validate.js`），不能纯数字、3~32 字符 |
| 注册邮箱 | 格式 + 唯一性校验；**面板代改不需要验证码** |
| 头像 | PNG / JPEG / WebP ≤2MB，走与客户端相同的魔数校验与落盘逻辑 |

为什么面板改邮箱不用验证码：这条路的信任前提是「运维已经确认了对方身份」
（通常是用户写信来说邮箱填错了）。客户端那条路信任的是「持有密码 + 持有新邮箱」，
两者本来就不是一回事。

改完**不踢会话**：token 里没有用户名和邮箱，用户下次拉 `/me` 就拿到新值。

## 7. 公告

### 7.1 面板

管理面板 →「公告」：

- 只有三样东西：**标题、内容、发布时间**；
- 发布时间**可改**（写错日期、提前发都是常态），留空 = 立即发布；
- 未来时间 = **定时发布**：客户端只查 `published_at <= now`，
  到点自动出现，不需要任何定时任务；
- 列表里「待发布」徽标表示还没到点；面板能看到它们（否则稿子在发出前就消失了）。

### 7.2 客户端

| 位置 | 行为 |
| --- | --- |
| 启动 | 拉 `/api/announcements/latest`，有公告就弹窗（标题 + 发布时间 + 正文） |
| 设置 → 市场 → 公告 | 历史列表，滚到底自动翻页（每页 20 条） |

- 启动弹窗**每次都弹**，不做「已读不再弹」：本地记已读的话，换设备、
  清数据就会重新弹，反而更难解释。嫌频繁就少发公告。
- 弹窗**让位给「账号已下线」提示**：两者都在启动时出现，
  用户此刻是来解决问题的，不是来看公告的。
- 拉公告失败**静默**：断网、服务器没起都很常见，不该在打开 App 的第一秒
  甩一个错误弹窗。历史页失败才会显示错误与「重试」。

### 7.3 时间与时区

- 库里存 UTC；接口一律返回**带 `Z` 的 ISO 字符串**；
- 面板用 `datetime-local` 输入本地时间，提交前转成 UTC ISO；
- 客户端解析后 `.toLocal()` 再显示。

这样面板、服务端、客户端三个时区不会互相打架。

## 8. 相关接口一览

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/auth/config` | 否 | 含 `deleteDelayDays` |
| GET | `/api/auth/me` | 是 | 返回 `deletion`（null = 正常） |
| PATCH | `/api/auth/me` | 是 | 只改用户名 |
| POST | `/api/auth/change-email/code` | 是 | 密码 → 新邮箱验证码 |
| POST | `/api/auth/change-email` | 是 | 密码 + 验证码 → 换绑 |
| POST | `/api/auth/delete` | 是 | 密码 → 申请注销 |
| POST | `/api/auth/delete/cancel` | 是 | 撤销注销 |
| GET | `/api/auth/sessions` | 是 | 当前有效设备 |
| GET | `/api/auth/sessions/history` | 是 | 历史登录（含已撤销 / 过期） |
| DELETE | `/api/auth/sessions/:id` | 是 | 踢掉某台设备 |

管理面板：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET / PUT | `/api/site` | 冷静期、扫描间隔、市场分页 |
| GET | `/api/users` | 用户列表（含 `ban` / `deletion`） |
| GET | `/api/users/:id` | 详情（资料 + 会话数 + userdata 占用） |
| PUT | `/api/users/:id` | 改用户名 / 注册邮箱 |
| POST | `/api/users/:id/avatar` | 上传头像（multipart，字段 `file`） |
| DELETE | `/api/users/:id/avatar` | 删除头像 |
| POST | `/api/users/:id/ban` | 封禁（`durationDays`，`-1` = 永久；`reason` 可选） |
| POST | `/api/users/:id/unban` | 解封 |
| POST | `/api/users/:id/status` | 老接口：`disabled` = 永久封禁 |
| POST | `/api/users/:id/delete` | 立即删除 |
| POST | `/api/users/:id/restore` | 撤销注销 |
| GET / POST | `/api/announcements` | 公告列表 / 新建 |
| PUT / DELETE | `/api/announcements/:id` | 改标题内容与发布时间 / 删除 |

公开接口（不需要登录）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/announcements?limit=20&offset=0` | 已发布的公告，按发布时间倒序 |
| GET | `/api/announcements/latest` | 最新一条；没有则 `announcement: null` |
