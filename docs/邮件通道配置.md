# 邮件通道配置

注册要邮箱验证码，所以服务端必须能发信。**发信通道是可切换的**：
改 `.env` 里的 `MAIL_DRIVER` 再重启，不用改代码、不用重新构建。

这份文档按「你手上有什么」来分：

| 你的情况 | 选 | 跳到 |
| --- | --- | --- |
| 有台 VPS，想完全自己掌控 | `smtp`（自建 Postfix） | [自建 SMTP](#1-自建-smtp) |
| 已经有一个邮箱（QQ / 163 / 企业邮） | `smtp`（用它当发件箱） | [用现成邮箱发信](#2-用现成邮箱发信smtp-最简单) |
| 不想折腾，愿意用海外服务 | `resend` | [Resend](#3-resend) |
| 已经在用 Twilio | `sendgrid` | [SendGrid](#4-sendgrid) |
| 主要用户在国内，在意送达率 | `aliyun` | [阿里云邮件推送](#5-阿里云邮件推送-directmail) |
| 只是想先跑通注册流程 | `console` | [本地开发](#6-本地开发console) |

## 0. 先搞清楚一件事：验证码邮件最容易被判垃圾邮件

一封「纯机器生成的 6 位数字」邮件，是垃圾邮件过滤器最警惕的形态。不管用哪条通道，
下面三件事都要在**发件域名**上配好，否则用户会在垃圾箱里翻验证码（然后来骂你）：

1. **SPF**：`v=spf1 include:<服务商的 SPF 记录> ~all`
2. **DKIM**：服务商给一段 TXT，贴到 DNS
3. **DMARC**：至少 `v=DMARC1; p=none; rua=mailto:你@你的域名`

自建 Postfix 时这三条要自己配；用第三方时控制台里会直接给你记录值，
复制到 DNS 即可。没有自己的域名、只能用 QQ 邮箱发信的话，送达率会明显差一些
（QQ 邮箱会把「代发」的邮件视为可疑），但个人项目够用。

## 1. 自建 SMTP

在 VPS 上装 Postfix（或已经有邮件服务的机器）：

```bash
sudo apt install postfix    # 选 "Internet Site"，域名填 mail.example.com
```

给服务端单独开一个账号，只用它发信（不要复用你的登录账号）：

```bash
sudo useradd -m -s /usr/sbin/nologin lemonmail
sudo passwd lemonmail
```

`.env`：

```ini
MAIL_DRIVER=smtp
MAIL_FROM=no-reply@example.com
MAIL_FROM_NAME=LemonLite

SMTP_HOST=mail.example.com
SMTP_PORT=587               # 587 = STARTTLS；465 = 隐式 TLS（则 SMTP_SECURE=true）
SMTP_SECURE=false
SMTP_STARTTLS=true
SMTP_USER=lemonmail
SMTP_PASSWORD=上面设的密码
SMTP_REJECT_UNAUTHORIZED=true
```

几个坑：

- **25 端口在大多数云厂商是封的**（防垃圾邮件），用 587。
- 如果 Postfix 和后端在同一台机器，可以用 `SMTP_HOST=127.0.0.1` +
  `SMTP_STARTTLS=false` + `SMTP_USER=`（不认证，只允许本机中继）。
  这种情况下**必须**确认 `mynetworks` 里只有 `127.0.0.1`，否则你会变成开放中继。
- 自签证书（内网自建）时把 `SMTP_REJECT_UNAUTHORIZED=false`，
  公网服务**不要**关它。

## 2. 用现成邮箱发信（SMTP，最简单）

如果你已经有一个 QQ 邮箱 / 163 邮箱 / 企业邮箱，可以直接拿它当发件箱。
**注意这里要填的是「授权码」，不是登录密码。**

### QQ 邮箱

1. 网页版邮箱 → 设置 → 账号
2. 找到「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务」
3. 开启 **SMTP 服务**，按提示发短信，拿到一串 16 位授权码
4. 配置：

```ini
MAIL_DRIVER=smtp
MAIL_FROM=你的QQ号@qq.com
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_SECURE=true          # 465 是隐式 TLS
SMTP_USER=你的QQ号@qq.com
SMTP_PASSWORD=那串授权码
```

### 163 邮箱

```ini
SMTP_HOST=smtp.163.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=你的账号@163.com
SMTP_PASSWORD=客户端授权密码
```

### 企业邮箱（腾讯企业邮 / 阿里云邮箱 / 自建）

一般 `smtp.exmail.qq.com:465`（企业微信邮箱）或 `smtp.mxhichina.com:465`，
同样用「客户端专用密码」。

> ⚠ 用个人邮箱发信会被限流（QQ 邮箱新号一天几十封，且容易被判垃圾）。
> 只建议给小规模自用或开发环境。

## 3. Resend

海外项目里最省事的一个：注册完拿到 API Key 就能发，免费额度 3000 封/月。

1. https://resend.com 注册
2. 添加并验证你的域名（它会给你几条 DNS 记录，照抄）
3. API Keys → 新建，复制 `re_` 开头的 key

```ini
MAIL_DRIVER=resend
MAIL_FROM=no-reply@你的域名
MAIL_FROM_NAME=LemonLite
RESEND_API_KEY=re_xxxxxxxx
```

没验证域名时只能用 `onboarding@resend.dev` 给自己发，别用在生产。

---

## 4. SendGrid

1. https://sendgrid.com 注册，完成 Sender Authentication（域名认证）
2. Settings → API Keys → 新建，权限给 `Mail Send` 即可

```ini
MAIL_DRIVER=sendgrid
MAIL_FROM=no-reply@你的域名
SENDGRID_API_KEY=SG.xxxxxxxx
```

## 5. 阿里云邮件推送 DirectMail

国内送达率最好，代价是配置步骤多一点。

1. 阿里云控制台 → 邮件推送 → 开通
2. **发信域名**：添加你的域名，按提示加 DNS 记录（SPF / MX / TXT 验证），等验证通过
3. **发信地址**：在「发信地址」里新建 `no-reply@mail.你的域名`，
   地址类型选「随机账号」，并设置 SMTP 密码（API 方式不需要，但建议设）
4. **AccessKey**：RAM 用户 → 新建，只授予 `AliyunDirectMailFullAccess`，
   记下 AccessKeyId / AccessKeySecret（主账号 AK 权限太大，别直接用）

```ini
MAIL_DRIVER=aliyun
MAIL_FROM=no-reply@mail.你的域名
ALIYUN_DM_ACCESS_KEY_ID=LTAI...
ALIYUN_DM_ACCESS_KEY_SECRET=...
ALIYUN_DM_ACCOUNT_NAME=no-reply@mail.你的域名   # 就是第 3 步建的发信地址
ALIYUN_DM_REGION=cn-hangzhou
```

> 阿里云对新账号有「日发信量」限制，先在控制台把额度调上来，
> 否则测试时会出现「有时能发有时发不出」。

## 6. 本地开发（console）

不想配 SMTP 时：

```ini
MAIL_DRIVER=console
MAIL_DEV_ECHO_CODE=true     # 把验证码直接放进接口响应的 debugCode
```

此时**邮件不会真的发出去**，验证码会打印在服务端控制台里；
客户端注册页会发现响应里有 `debugCode` 并自动填进输入框，
所以整条注册链路照样能跑通。

⚠ 这两项都只该出现在开发机上。生产环境里 `console` 意味着「谁都能注册」，
`MAIL_DEV_ECHO_CODE=true` 意味着「验证码直接送给请求方」。

## 7. 配完怎么验证

**看启动日志**（服务端每次启动都会打印一行）：

```
✓ 邮件 smtp → 就绪（smtp.qq.com:465），发件人 no-reply@example.com
```

如果显示 `! 邮件 ... 未就绪（没有配置 SMTP_HOST）`，就按括号里的原因补配置。

**直接调一次接口**：

```bash
curl -s -X POST http://127.0.0.1:3000/api/auth/email-code \
  -H 'Content-Type: application/json' \
  -d '{"email":"你的邮箱@example.com"}'
```

正常返回：

```json
{"ok":true,"data":{"sent":true,"email":"...","cooldown":60,"expiresIn":600,"driver":"smtp"}}
```

| 返回的 `error.code` | 含义 |
| --- | --- |
| `mail_not_configured` / 503 | 服务端没配好邮件通道（看启动日志那一行） |
| `email_taken` | 这个邮箱已经注册过 |
| `code_cooldown` | 60 秒内重复索要（`detail.retryAfter` 是剩余秒数） |
| `code_rate_limited` | 超过小时配额（防刷） |
| `invalid_email` | 邮箱格式不对 |

**收不到邮件时按这个顺序查**：服务端日志里的 SMTP 错误码 → 垃圾箱 → 发件域名的
SPF/DKIM 是否生效（`dig txt 你的域名`）→ 服务商控制台的发送记录。

## 8. 登录二次验证（可选）

注册之外的第二种用法：**登录也要验证码**。在 `.env` 里打开：

```ini
AUTH_LOGIN_CODE=on      # 默认 off
```

打开后登录流程是：

```
输入账号 + 密码 → 点「获取验证码」（服务端先核对密码，对了才发信）
           → 邮箱收到 6 位码 → 填入 → 登录
```

客户端不需要改任何东西：它启动时读 `GET /api/auth/config`，
发现 `loginCode: true` 就自动把验证码输入框显示出来；
服务端关掉后它也会自动隐藏。

几个必须知道的取舍：

- **密码先于验证码校验**。反过来的话，不知道密码的人也能用「这个码对不对」
  试探账号是否存在，还会给任意账号免费发信。
- 登录验证码与注册验证码共用限流配额（同一张表）：分开算会被「注册 10 封 +
  登录 10 封」绕过。
- 开了它之后，**邮件通道挂了就等于全员登不进去**（已登录的会话不受影响）。
  所以要么通道稳定，要么别开。

相关问题排查见第 7 节；`email_codes` 表里 `purpose='login'` 的行就是它。

## 9. 换通道要注意什么

- 换 `MAIL_DRIVER` 只需**重启**服务端，客户端不用动（它根本不知道用的是哪条通道）。
- 已签发的验证码**不会**因为换通道而失效（存在 `email_codes` 表里）。
- 登录验证码（`purpose='login'`）和注册验证码互不影响：同一个邮箱可以在
  「刚注册完」的情况下立刻登录，不会撞冷却 —— 冷却只按同一用途算。
- `MAIL_FROM` 必须换成新通道验证过的地址，否则会被拒。
